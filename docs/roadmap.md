# Scope and next steps

## Current reference

Local CLI plus an authenticated web portal, custom-ID QR SVG, SQLite asset/issue/event storage, normalized web image evidence, role-controlled assignment/review, CSV export and status/action history. No mobile camera decoder, location validation, immutable audit or external railway API is included.

## Next priorities

1. Confirm original problem statement, component scope and existing project assets.
2. Demonstrate QR scanning on mock labels and record repeatable results.
3. Add actual prototype screenshots/video, confirmed contributions and project report/PPT when supplied.
4. Authenticated web roles, assignment and normalized evidence access are now implemented. Next: security review, TLS deployment, retention and backups before real shared use.
5. Design a mobile capture workflow, QR decoder and offline synchronization with duplicate/conflict handling.
6. Define an AI task (e.g. image-quality triage or specific defect suggestion), collect authorized labelled data and evaluate on held-out cases. Keep human review and uncertainty explicit. No trained model currently exists.
7. Explore direct-part marking only with actual material/owner requirements, engineering validation and specified equipment.
8. Integrate UDM/TMS only through authorized documented interfaces, with contracts, test environment and error/retry/audit handling. No endpoint or credential has been invented.

The current custom ID is not a GS1 identifier. Laser marking, AI, real-time rail monitoring, predictive maintenance and automatic repair dispatch are proposed ideas, not delivered features. Do not create a hardware-verified release or claim a railway deployment without evidence.
